PKISquire CA Web Server User Manual

This manual explains how to operate the PKISquire CA web server UI and related web endpoints. It is based on current route and handler behavior in the codebase.

Source files: app.py, users.py, x509_keys.py, x509_profiles.py, x509_requests.py, events.py. Updated: 2026-02-27.

1) Purpose and Audience

  • Audience: PKI operators, security admins, and helpdesk engineers using the web UI.
  • Purpose: run daily certificate lifecycle tasks safely and consistently.
  • Scope: UI workflows plus related server endpoints used by operators.

2) Prerequisites

  • Install dependencies: pip install -r requirements.txt
  • Run database migration: python migrate_db.py
  • Start server: python app.py
  • Main config file: config.ini

Runtime edition is controlled by PIKACHU_EDITION: community or enterprise.

Community: core UI/API Enterprise-only: EST, SCEP, OCSP, challenge passwords, API tokens, LDAP/PQC extras

3) Authentication and Access Model

  • Login page: /users/login
  • Self-registration page: /users/register (enabled only if allow_self_registration=true)
  • Logout: /users/logout
  • Most pages require login via @login_required
  • Non-admin users generally see only their own keys, profiles, CSRs, and certificates

Admin-only workflows include user management (/users/manage) and elevated policy/system controls.

4) Quick Start (10 Minutes)

  1. Log in at /users/login.
  2. Create a key at /generate.
  3. Create a profile at /profiles/new.
  4. Generate CSR at /requests/generate.
  5. Sign CSR at /sign.
  6. Verify/download certificate at /certs.

5) Task-Based Workflow Guides

Step A: Create Key

Go to /generate, choose key type (RSA/EC/PQC), and save.

Step B: Create Profile

Go to /profiles/new, define OpenSSL profile content, save profile.

Step C: Generate CSR

Go to /requests/generate, pick key + profile, create CSR.

Step D: Sign CSR

Go to /sign, choose CSR and RA policy, submit signing.

Step E: Manage Certificate

Use /certs to view, download, revoke, delete, export PFX.

Step F: Validate and Audit

Use /va, /status/<serial>, /events.

6) Main Pages and How to Use Them

Dashboard and Certificate Inventory

  • / or /dashboard: summary counters and activity data
  • /certs: certificate table with ownership filtering
  • /view/<id>: certificate details and key format views
  • /revoke/<id> (POST): marks certificate revoked and rebuilds CRL
  • /delete/<id> (POST): removes certificate record
  • /downloads/<id>: download PEM certificate
  • /downloads/pfx/<id> (POST): build and download PFX (password required)

RA Policies and Extension Config

  • /ra_policies: list policies (admin sees all; user sees own + system)
  • /ra_policies/new: create policy, optional clone via ?clone_id=
  • /ra_policies/<id>/edit: edit policy (non-admin has restrictions on system policies)
  • /server_ext: edit extension config linked to selected/default policy
  • /get_server_ext_content: fetch policy extension content for UI auto-load

Keys, Profiles, and CSRs

  • /generate: create private/public key pair
  • /keys: list keys
  • /keys/<id>: view key details and format conversions
  • /profiles/: list saved certificate profiles
  • /profiles/new: create profile manually
  • /requests: list CSRs
  • /requests/generate: generate CSR from selected key/profile

Validation and CA Material

  • /va: CRL content + OpenSSL CRL parse + revoked list
  • /ca: root and subordinate CA certificate details
  • /view_root, /view_sub: direct certificate detail pages
  • /downloads/crl, /downloads/chain

Users and Account

  • /users/manage: admin user management
  • /users/add, /users/delete/<id>, /users/reset_password/<id>
  • /account: theme and password actions
  • /change_password: local users only; LDAP users cannot change in-app

7) Permissions and Roles

  • Admin: full visibility across users; can manage users, system policies, and global operations.
  • User: sees/changes own objects only (keys, profiles, CSRs, certs), with limited policy operations.
  • Owner/Admin endpoints: object-level checks enforce ownership for view/edit/delete actions.
  • Edition gates: enterprise-only routes return 404 in community mode.

8) Input and Format Requirements

  • CSR input: PEM, DER, or base64 accepted in signing/enrollment flows.
  • Profile content: OpenSSL .cnf-style extension/request sections.
  • Certificate serial: hexadecimal string is used in status/revocation flows.
  • PFX export: requires matching private key in DB and non-empty pfx_password.
  • Theme/account forms: validated enum-style values, then persisted in user settings.

9) Protocol Endpoints (Machine Clients)

These endpoints are mainly for client/device integrations rather than manual browser use.

  • /ocsp, /ocspv: OCSP responders
  • /.well-known/est/cacerts and /.well-known/est/simpleenroll
  • /scep, /cgi-bin/pkiclient.exe, /mobileconfig
  • /api/challenge_passwords, /challenge_passwords (enterprise challenge flow)
  • /api/keys/<name>/private, /api/keys/<name>/public (enterprise token API over HTTPS, with optional TRUSTED_HTTPS mTLS)

The Challenge Passwords page lists all challenge-password tokens generated for certificate enrollment. These tokens can now be created as single-use, reusable until expiry, or reusable without expiry. Single-use passwords are consumed after one successful SCEP enrollment, while reusable and unlimited passwords remain valid for later SCEP enrollments and track how many times they have been used.

In Community edition, enterprise feature gates return 404 for blocked routes.

10) Admin and Operations Pages

  • /logs: live log view page
  • /logs/last?n=300: tail endpoint used for polling (plain text)
  • /config: protected config viewer; requires session secret check against DELETE_SECRET
  • /inspect: inspect PEM/DER/PKCS/OCSP objects
  • /events and /users/events: audit event streams

12) Common Issues and Fixes

  • Cannot access feature page: check edition (community vs enterprise) and user role.
  • Self-register blocked: set allow_self_registration=true in config.ini.
  • PFX export fails: server cannot match certificate public key to stored private key.
  • CSR/profile errors: verify OpenSSL profile structure and ownership permissions.
  • Password change blocked: LDAP users must change password in LDAP/AD, not in this app.

13) Security and Safety Notes

  • Treat private keys, PFX exports, and secrets as sensitive material.
  • Limit admin accounts and review /events and /users/events regularly.
  • Use HTTPS deployment and protect access to /config and logs.
  • Revoke compromised certificates immediately and redistribute updated CRL.

14) FAQ

  • Why do some routes return 404? They are enterprise-gated and disabled in community mode.
  • Why can a user not see an object? Ownership filtering is applied for non-admin users.
  • Why is password change blocked? LDAP users are managed externally by LDAP/AD.
  • Why does PFX download fail? No matching private key is available for the certificate.

15) Glossary

  • CA: Certificate Authority that signs certificates.
  • CSR: Certificate Signing Request generated from a private key.
  • CRL: Certificate Revocation List of revoked serials.
  • OCSP: Online certificate status protocol.
  • RA Policy: rules/extension profile used during certificate issuance.
  • PFX/PKCS#12: bundle format containing certificate + private key (+ chain).
